# Sport Celebrations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After posting or joining a game, play a short sport-specific animation with sound and a vibration, skippable, with Profile switches to turn animations or sounds off.

**Architecture:** Pure rules live in `src/utils/celebration.js` (scene choice, durations, cue timing, captions, what plays given settings). They're tested with Node. A full-screen `Celebration` overlay drives one Reanimated `progress` value from 0 to 1 and passes it to one SVG scene per sport. Sound (`expo-audio`) and vibration (`expo-haptics`) fire from timeouts derived from the rules. Settings are two AsyncStorage flags.

**Tech Stack:** Expo SDK 57, React Native, react-native-reanimated 4.5.1, react-native-svg 15.15.4, expo-audio, expo-haptics, AsyncStorage; Node `node:test`; Python 3.11+ stdlib (`wave`, `struct`, `math`, `random`, `unittest`).

**Spec:** `docs/superpowers/specs/2026-10-14-sport-celebrations-design.md`

## Global Constraints

- Durations: created / weekly **2500 ms**, joined **1200 ms**. Reduce Motion: still frame shown **1000 ms**.
- Captions, exactly: `Game on!`, `Weekly game on!`, `You're in!`.
- Scenes: `soccer`, `basketball`, `flag_football`, `track`, `ultimate`, and the fallback `confetti`.
- Stage **320 × 220** points. Colors: forest `#17442F`, clay `#B9441B`, sage `#D5E2D0`, cream `#F4F0E6`, ink `#172019` (use `COLORS` tokens).
- Sounds: `assets/sounds/{whistle,swish,cheer,pistol,whoosh}.wav`, mono, 22,050 Hz, under 1 s, peak > 0.1 and < 0.95. Generated by `scripts/make_sounds.py` with a fixed seed.
- iOS audio: `playsInSilentMode: false`.
- AsyncStorage keys: `grassroots.celebrations.animations`, `grassroots.celebrations.sounds`. Both default **on**.
- The game is saved before the overlay shows. The overlay never writes data, and sound or vibration errors are swallowed (logged only).
- Install new packages with `npx expo install expo-audio expo-haptics`.
- Follow the user's preference: commit messages and PR text in plain English. Comments explain why.

## Review Focus

1. **Double tap or skip while finishing:** `onDone` must run exactly once. A tap at the same moment the timer ends must not close Create Game twice. *(Task 5 test: `finishOnce`.)*
2. **Skip or unmount mid-scene:** no sound or vibration may fire after a skip or after the overlay unmounts (for example, the modal is closed). *(Task 1 test on `cueSchedule`; Task 5 clears every timeout on finish and on unmount.)*
3. **Sport written differently:** `'Soccer'`, `' soccer '`, `null` and `'flag football'` must not crash. Known sports map case-insensitively; anything else gets `confetti`. *(Task 1 test.)*
4. **Storage unreadable or holding junk:** a missing, garbage or failing AsyncStorage value means **on**. *(Task 1 test on `flagFromStorage`; Task 3 catches read errors.)*
5. **Sound fails to load (asset missing, audio session busy):** the animation still finishes and `onDone` still runs. *(Task 3: `playCue` never throws.)*

### Task 2: Generated sound effects

**Files:**
- Create: `scripts/make_sounds.py`
- Create: `scripts/test_make_sounds.py`
- Create: `assets/sounds/whistle.wav`, `swish.wav`, `cheer.wav`, `pistol.wav`, `whoosh.wav` (generated)
- Modify: `.github/workflows/ci.yml` (python job: one extra step)

**Interfaces:**
- Produces: `make_sounds.py` functions `whistle()`, `swish()`, `cheer()`, `pistol()`, `whoosh()`, each returning `list[float]` in [-1, 1] at `RATE = 22050`; `write_wav(path, samples)` writes 16-bit mono; `main(out_dir="assets/sounds")` writes all five. `random.seed(7)` at the start of `main`.

- [ ] **Step 1: Write the failing tests** in `scripts/test_make_sounds.py` (`unittest`). They import `make_sounds`, generate into a temporary folder, then for each of the five files check:
  - it opens with `wave` and has 1 channel, a 2-byte sample width and a rate of 22050;
  - its duration is under 1.0 s;
  - its peak absolute sample / 32768 is > 0.1 and < 0.95.
  
  Also test determinism: generating twice gives byte-identical files.

- [ ] **Step 2: Run them and confirm they fail.** Run: `python -m unittest scripts/test_make_sounds.py -v` (from the repo root, with `scripts` on the path via `sys.path.insert` in the test). Expected: ImportError.

- [ ] **Step 3: Implement the generators** in `scripts/make_sounds.py`, Python standard library only:
  - **whistle:** about 0.45 s. A 2,800 Hz sine with fast 30 Hz frequency trills (±120 Hz) and a little breath noise. Attack 10 ms, release 60 ms.
  - **swish:** about 0.35 s. White noise through a simple one-pole high-pass, with an envelope that rises and then falls fast.
  - **cheer:** about 0.9 s. It starts with a 60 ms low "thump" (a 90 Hz sine falling to 50 Hz), then many detuned 200–900 Hz voices plus noise, swelling and fading.
  - **pistol:** about 0.3 s. A 5 ms noise burst, then a fast-decaying low-passed noise tail.
  - **whoosh:** about 0.5 s. Band-limited noise whose filter sweeps low to high to low, under a sine envelope.
  
  Normalize each sound to a 0.8 peak before writing.

- [ ] **Step 4: Generate the files and run the tests.** Run: `python scripts/make_sounds.py && python -m unittest scripts/test_make_sounds.py -v`. Expected: five files in `assets/sounds/`, and all tests pass.

- [ ] **Step 5: Add a CI step** to the python job: `Check celebration sounds`, run `python -m unittest scripts/test_make_sounds.py -v` with `working-directory: .` (the repo root).

- [ ] **Step 6: Commit**: `git add scripts/make_sounds.py scripts/test_make_sounds.py assets/sounds .github/workflows/ci.yml && git commit -m "Celebrations: generated whistle, swish, cheer, pistol and whoosh sounds"`

### Task 3: Settings, sound and vibration helpers

**Files:**

- Create: `src/lib/celebrationSettings.js`
- Create: `src/lib/celebrationSound.js`

**Interfaces:**
- Consumes: `flagFromStorage`, `SOUNDS` (Task 1).
- Produces:
  - `loadCelebrationSettings(): Promise<{ animations: boolean, sounds: boolean }>` reads both keys and runs each through `flagFromStorage`. Any thrown error → `{animations:true, sounds:true}`.
  - `saveCelebrationSetting(key: 'animations'|'sounds', on: boolean): Promise<void>` stores `'true'`/`'false'` and swallows errors.
  - `playCue(cue: { sound?: string, haptic?: true }): void` never throws. A haptic cue → `Haptics.notificationAsync(Haptics.NotificationFeedbackType.Success)`. A sound cue → a cached `createAudioPlayer(require(...))` per sound; call `seekTo(0)` then `play()`.
  - `prepareCelebrationAudio(): Promise<void>` calls `setAudioModeAsync({ playsInSilentMode: false })` once and swallows errors.

**Interfaces:**
- Consumes: Tasks 1, 3 and 4.
- Produces:
  - `finishOnce(fn): () => void` returns a function that calls `fn` the first time only (pure, tested).
  - `<Celebration sport mode isWeekly title subtitle settings onDone />`:
    - `mode` is `'created'|'joined'`; `settings` is `{animations, sounds}`.
    - It reads Reduce Motion via `AccessibilityInfo.isReduceMotionEnabled()`.
    - It computes `playbackFor`. If `!show`, it calls `onDone` immediately and renders nothing.
    - Otherwise it shows a full-screen `Pressable` (cream at 0.92 opacity with `BlurView intensity 30`), the scene and the caption (Fraunces `FONTS.display`, 34) with the subtitle under it.
    - It animates `progress` 0→1 with `withTiming(1, { duration, easing: Easing.linear })`, or sets `progress.value = 1` and waits `STILL_MS` when `!animate`.
    - It schedules `cueSchedule(...)` with `setTimeout → playCue`.
    - It ends on the timer or on tap through one `finishOnce(onDone)`, and clears every timeout on finish and on unmount.
